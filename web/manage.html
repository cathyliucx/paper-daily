使用 GitHub 账号管理，无需令牌

本站只展示论文。管理操作交给 GitHub 自己的登录和权限校验，页面刷新后不会再要求填写授权令牌。

研究兴趣

在 GitHub 编辑 config/interests.json 中的 topics：名称和描述可用中文，keywords 使用英文。需要严格区分概念时，保留 required_keyword_groups；组内为“或”，组间为“且”。

新增兴趣时在列表中添加一个对象；保留已有来源和其他兴趣。点击 GitHub 的 Commit changes 保存后，会自动运行采集并更新网页。

模型密钥配置一次，采集自动使用

模型 API 密钥保存在 GitHub Actions Secrets，日常查看论文、运行采集都不需要重新输入。已有密钥可以继续保留；只有失效、轮换或更换服务商时才需要更新。

DeepSeek 首次配置：在 Secrets 新建 DEEPSEEK_API_KEY，填入 DeepSeek 的 API 密钥并保存。默认接口和模型已经支持，不必反复填写。

如果已经配置过模型密钥，请保留现有设置，不必再次新增。密钥不会写入网页或公开源码，GitHub 也不会回显。

其他服务商、旧版配置与自定义模型

已有 LLM_API_KEY 完整模型配置继续生效，优先使用其中的接口和模型。普通 API key 也受支持，可搭配 Variables：LLM_BASE_URL 指定基础地址，LLM_MODEL 指定模型 ID。

DeepSeek 默认地址为 https://api.deepseek.com/v1，默认模型为 deepseek-chat。只使用默认设置时不需要额外填写变量。以后主动更换服务商时再更新密钥与对应配置。

更新论文与清理缓存

  1. 打开下方 Paper Daily 工作流，点击 Run workflow。
  2. 普通更新保持 clear_cache = false；重建历史论文列表时填 clear_cache = true。
  3. lookback_days 填写检索天数，例如 7。再点击绿色的 Run workflow 确认。
  4. 等待任务成功发布后，刷新论文页。任务失败时在 GitHub 查看日志。

清理缓存会重新生成论文列表，研究兴趣和模型密钥不会被删除。仅打开入口不会启动采集。现有每日自动采集继续运行。
